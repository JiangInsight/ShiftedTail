# Arithmetic, witness degrees and exact boundary stress

The strict fused verifier uses binary64 nearest-even intermediates. It rounds the complement and its product with the old coordinate separately, calls explicit FMA and projects onto the probability range. It clips the contiguous tails of its window at 1e-15. Its radius is nextUp(d times nextUp(8 epsilon + 2 tau)), where epsilon is 2^-52 and d counts factors actually consumed before stopping. Since the exact recurrence is nonexpansive, a projected unit coordinate incurs at most one epsilon for the rounded complement, another for the product and another for the fused rounding. The last operation rounds a value no larger than 1+2 epsilon. These absolute-error bounds include subnormal values under gradual underflow. Clipping changes the resulting coordinate by at most tau + epsilon. Boundary coordinates outside the active window are already zero or one. Degrees are uint32, so d converts to binary64 exactly. An early return at the upper endpoint uses the monotonicity of the exact tail under additional factors.

The non-FMA build computes both interval endpoints at every visited coordinate. It widens the complement, each product and the sum, constraining endpoints to [0,1]. The upper end of the truncated array is min(k,number of trials). It omits threshold clipping and uses no cumulative error budget. Monotonicity of addition and multiplication on nonnegative operands proves the inclusion. Both implementations round the row discrepancies upward and accept only if both are at most 1e-9.

The executable checks that every participating OpenMP worker uses round-to-nearest, ties-to-even, subnormal operands and gradual underflow of results. The build checks IEC 60559 binary64 and binary64 intermediate evaluation. Strict compiler flags and prohibition of reassociation remain required. The two probes rejected deliberately enabled upward rounding, FTZ and DAZ on this x86-64 host. The non-FMA build was compiled with -mno-fma; the fused build used explicit std::fma and -mfma. Both used GCC 16.2.0 (MinGW-w64 UCRT), -O2 -fopenmp -fno-fast-math -frounding-math -ffp-contract=off. Each formal timing used a single worker on Intel Core Ultra 9 275HX under Windows. This validates these binaries on this host. An optimized arbitrary binary is outside that specification.

## Running the checker

The source archive contains the complete kernels, standalone checker, launcher, graph converter, test drivers, scripts and the claimed Wiki-Pe table and removal-order witnesses. In an extracted copy on x86-64, set CXX to a GCC compiler path and GMP_ROOT to the GMP installation (headers, libraries and runtime). Use Python 3.11 or later. Run the following from its top directory.

    python -B code/review4_arithmetic/run.py build endpoint boundary

For the Wiki-Pe test, obtain the French graph's fr.csv.zip from the [Netzschleuder network repository](https://networks.skewed.de/net/wiki_talk/files/fr.csv.zip). The checked archive and output graph SHA256s are in the converter; the recorded threshold and order hashes are in wiki_inputs.json. Install numpy and pandas to convert the graph, set WIKI_CASE to the extracted wiki directory (absolute path), then run

    python -B code/review4_arithmetic/prepare_wiki.py fr.csv.zip wiki/WikiTalkFR.bin
    python -B code/review4_arithmetic/run.py wiki

To check other candidate files, use the launcher. The Windows build commands above produce results/review4_arithmetic/fma.exe and portable.exe. Select the latter explicitly on a machine without hardware FMA. Each executable expects the graph, candidate values, removal order and thread count.

    python code/review4_arithmetic/verify_checked.py G.bin values.thr removals.bin 1 --fma-exe results/review4_arithmetic/fma.exe --portable-exe results/review4_arithmetic/portable.exe

The launcher rereads the identical inputs with the outward kernel only on fused exit code 3 (a row-error budget exceeded). Its --portable option starts directly in the outward kernel. An invalid input or unsupported float environment fails. On a different IEEE binary64 platform the portable path can be built with a strict C++17 compiler, OpenMP, no fast math or reassociation, no implicit contraction and -DUCORE_NO_FMA. The recorded experiment uses the x86-specific compiler options shown in build.json. Runtime checks cannot repair a binary built with unsupported optimization settings.

## Numerical evidence

The Wiki-Pe row file has 2,279,811 entries. The largest original graph degree is 1,095,589 (zero-based vertex 96). Before shortcuts, maxima over all lower/upper witness degrees are 2,258/2,237. There are 10,510 candidate-near-zero lower shortcuts and 70,030 candidate-near-one upper shortcuts. Another 0/13,184 nonshortcut neighborhoods have fewer than k eligible neighbors and return the exact structural zero. In the fused build, the largest actual lower/upper convolutions process 244/235 factors or 13,274/10,236 individual cell evaluations. Its D-minus and D-plus reproduce the original checker values: 9.9661635543987208e-13 and 1.5545342790801444e-12. The independent non-FMA backend also accepts. It computes the same D-minus and a D-plus of 9.957590307863031e-13. Its corresponding maxima are 2,258/235 factors and 33,855/12,665 cells. Full raw totals and separate one-process timings (1.51 versus 31.95 seconds, including read and integrity checks) are in witness_stats.csv.

On a 280,000-leaf zero-probability star, all thresholds are exactly zero. Submitting the hub first gives one upper witness with 280,000 zero factors. The fused allowance causes D-plus=1.0573799150320711e-9 and the checker declines that row. The non-FMA checker accepts the same file, D-plus=4.1501563657229294e-318. The same experiment with every edge probability and every submitted threshold equal to 2^-60 gives D-plus=1.0573799141647094e-09 fused and 2.4286041928564138e-13 portable. One edge attains the claimed threshold and every nonempty feasible positive-level set contains a leaf. Portable success on that example is an observation, not a promise that every exact table will pass a finite-precision check.

endpoint_cases.csv contains 494 independently verified vectors/levels per kernel. The oracle forms the entire integer probability-mass polynomial and sums its high coefficients. Cases include exact zero and one, subnormal probabilities, the smallest normal, adjacent ULPs at both clipping thresholds, long denominators and seeded heterogeneous neighborhoods. All 988 enclosures contained the exact rational answer. The largest exact rational tail denominator was 12,889 bits. The validation checks every computed endpoint against the rational number before storing its summary.

boundary_cases.csv uses the production queue and GMP refiner with optional instrumentation. Candidate brackets are provided for a single level. The full output vectors are compared byte-for-byte against a separate synchronous exact-PMF deletion oracle. The table also records an order-sensitive checksum and extrema. Times cover only refinement after receiving the brackets. Graph file reading, exact calls and total refinement are recorded separately. Successive confidence queries in one case share the loaded graph; the first query incurs cold graph-loading cost. Timings are single observations, and instrumentation includes integer-size observations.

At confidence 1/2 all 8,192 endpoints of 4,096 probability-half edges enter GMP and survive; the next binary64 confidence excludes them all. Equal subnormal edges exercise the minimum positive binary64 probability, including equality and its successor. The heterogeneous regular 64-vertex case pairs complementary edge probabilities and has odd degree 63, giving exact survival 1/2 at k=32. Its denominator reaches 3,184 bits and a cross-multiplication operand reaches 3,237 bits. In a 256-vertex cycle at k=2, a single edge at the predecessor of 1/2 produces a removal cascade at 1/4. There are 510 checks and 254 revisits. All 14 graph queries agree with the independent oracle. At d factors the denominator requires 1+sum(b_i) bits (as large as 1+1,074 d for binary64 probabilities); each stored numerator is no larger than that denominator. Cross multiplication can require another max(a,53) bits. This implementation recomputes exact state at a revisit because the current neighbor set can change after removal.
