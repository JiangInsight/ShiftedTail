# Reproducing the matched experiment

The input identifiers and source graphs are recorded in [the earlier input manifest](../study/input_manifest.json). Run the scripts from the Paper 2 root. They use its existing graph collection and executables, a 32 GiB Windows job-object launcher, and a large scratch directory at `C:/vldb_paper2_fair`. Keep timed jobs serial. On this host the benchmark writes to the same C: volume for every competitor. The next invocation reuses completed records. To reproduce from scratch, use a fresh results directory and scratch directory together. Keep raw failed and censored records.

1. Check out the [Gatd author code](https://github.com/AbigailJixiangyuyu/uco-gpu) at `88b5ba7f60560363bc1579c7ee7984ee3541be6e`. The existing repaired source and the two portability/reduction patches are documented in the [original study](../study/PROTOCOL.md). The additional [output adapter patch](../../code/fair_study/gpu_sparse.patch) is relative to the corrected source directory. The resulting local tree is in `baselines/gatd_win_matched`. Run its `build_windows.bat` from within this directory. This adapter ranks and packs eligible entries only when requested through `GATD_SPARSE_OUTPUT`.
2. Use the [Dai author code](https://github.com/qq-dai/UncertainCore) at `315dee85ff5aae487c296a99fb600304bbee0f24` in the scratch directory under `UncertainCore`. The driver uses the original graph preparation and calls algorithm 4 with top-k pruning and algorithm 6. Code is compiled with GCC/OpenMP, native architecture and O3. The local UCRT64 GSL 2.8-1 package SHA-256 is `841bb5f98a3a008bac2561483e230f7ecb44326c41161ce53634d2ce7a0ab3f5`. The GMP 6.3.0-2 SHA-256 is `e82a75968a556484a50084578238a84eb60fb93e34986fd6695c537975bd39ea`. Extract their `ucrt64` subdirectory into scratch `deps`.
3. Build the CPU drivers with `code/fair_study/build_cpu_baselines.ps1 -AllQueries`. The exact-boundary path disables fused contraction in the interval arithmetic and invokes GMP for inconclusive comparisons. UCEF is built with the same AVX2 MSVC profile as CTD, OptiUCF and the proposed CPU solver.
4. Run `python -u code/fair_study/run_queries.py` for the direct author algorithms and the point-lookup pilot. Then run `python -u code/fair_study/run_matched.py` for the same-input and same-output benchmark. Derived inputs, reference files and removal permutations are retained under scratch. The [local protocol](PROTOCOL.md) defines the sampling, caps and numerical checks.
5. Run `python -u code/fair_study/run_extension.py` for the exact small-graph check, inclusive queries and UCEF timings. On the real query datasets the driver charges fresh build, verify, rank and dense result generation. Read the per-query prefix timestamps and compare answers vertex by vertex.
6. Run `python code/fair_study/summarize.py`. It verifies the expected cohorts and checked output sizes before producing the report, summary tables and figure. Individual logs, command options and hashes are under `matched`, `query`, and `extension`. The per-arm status distinguishes validation failure, process error, timeout and completion.
