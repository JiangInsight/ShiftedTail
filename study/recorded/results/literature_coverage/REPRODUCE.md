# Run the literature-aligned extension

Use the executables and toolchain from [the matched baseline build](../fair_study/REPRODUCE.md). Commands below start from the Paper 2 root. The Windows scratch directory is C:/vldb_paper2_fair. Preserve the existing results when changing solver builds or policies.

1. Put an unmodified checkout of [the KDD artifact](https://github.com/fgullo/uncertaincores/tree/370b2dbcaa02a3466a2afd10e24cd52019c3edb3) in scratch/bonchi_public and [the UKGE data](https://github.com/stasl0217/UKGE/tree/5049b84501657abc44c36dd7d2db5f8519e5ee8f) in scratch/UKGE_source. Place the [timestamped HepPh zip](https://nrvis.com/download/data/dynamic/ca-cit-HepPh.zip) in scratch/hepph_events.zip. Web-Google and Cit-Patents use the original pre-holdout CSR files from the Paper 1 SNAP converter. The per-input JSON files contain hashes of source data, prepared graph, cardinalities and projection rules.
2. Run `python code/fair_study/literature_coverage.py`. It constructs and independently checks a full reference table on each input, then rotates the competitor order. Keep case-level metadata in results/literature_coverage/runs and large arrays in scratch/literature_coverage. Each successful timing must match the verified output dimensions and meet the numerical tolerance for its implementation.
3. Run `python code/fair_study/literature_queries.py`. This uses the original KDD and Dai solver code. For Flickr, the supplied beta file is copied from the author artifact. The LB main suppresses result writing; BonchiBoundOutput calls the existing result-writing routine with the same underlying solver. The one-processor JVM setting constrains JVM parallelism; these wall times include its startup, graph parsing and text outputs. Credentials and external services are unnecessary.
4. Run `python code/fair_study/large_literature.py`. The script downloads public event archives, aggregates every unordered pair and builds complete CSR inputs. The French talk archive is [here](https://networks.skewed.de/net/wiki_talk); Deli uses the [tag-item archive](https://networks.skewed.de/net/delicious). Run one large timed process at a time. Preserve the raw default CPU failure logs. A completed competitor initially marked unverified keeps that original record and its output for subsequent verification.
5. Run `python code/fair_study/deli_memory.py` and `python code/fair_study/extended_caps.py`. For the memory diagnostic, the first script changes the number of simultaneous levels in a scratch translation unit from the requested thread count to one; it retains the 24-thread OpenMP sweep. The same-input HepPh regression requires identical output to the frozen implementation. The script certifies Deli, compares both saved competitor outputs, and separately times the same executable writing only the canonical threshold file. The final timing must reproduce the certified output hash. The second script records separate 1,800-second trials. The results distinguish elapsed time through a limit, host memory exhaustion, numerical failure and success.
6. Run `python code/fair_study/check_ccas_input.py` for the cross-paper DBLP edge check and `python code/fair_study/literature_report.py` to regenerate the final tables. [Numerical results](RESULTS.md) · [Baseline provenance](ALIGNMENT.md) · [Workload selection and caps](PROTOCOL.md).
