# Matched lower-bound controls

Each invocation constructs every level of the complete Twitter or undirected CN15k projection from the literature-coverage cohort. The input is its binary CSR with the previously prepared edge probabilities, model 5. The graph hashes in the session records identify the inputs. Every run uses one CPU worker, writes the values and its own removal order, and checks that pair in a fresh process. Build wall time starts before loading the graph and includes the probability sort, cache construction, final output and process exit. The independent checker is timed separately. The CSV reports three repetitions as their median and range.

The three arms share support-core initialization, adjacency traversal for probability evaluation, heap, scheduling, global floor, and degree/previous-upper shortcuts. All use the same grouped-binomial-seed option, indexed queue and coalescing. Concentration screening is off in this matched baseline, as in the published single-worker mechanism cohort. The seed takes effect only if its frequency test passes. Output orders can differ between bound policies.

* **Shift** uses the historical survival lower endpoint at the first stored offset at least as large as the number of deleted neighbours.
* **Retained** takes the larger of the top-k surviving probability product and the binomial survival for the current degree and smallest surviving probability. This reconstructs the two lower bounds of OptiUCF. Its additional upper binomial bound, activation strategy and separate kernel are omitted to isolate the lower-bound choice. This arm keeps the zero offset and the terminal zero-bound sentinel.
* **Combined** takes the maximum of both bounds. In exact arithmetic it is at least as tight as either operand on the same notification. Its peel path and total time may differ.

The retained arms sort each adjacency by decreasing probability once and scan the index for the first k live neighbours and the last live neighbour. Sorted adjacency reads, successful and rejected, count toward ranked_probes. Each level caches up to 250,000 (degree,pmin) binomial values. retained.hpp computes a directed lower enclosure using successive binomial masses from the shorter side of the distribution. It normalizes mantissas with separate integer exponents and rounds products, ratios and sums outward. For the left tail it rounds the CDF upward before subtracting from one. The probability of k successes on the top k edges bounds survival from below, as does stochastic domination by Bin(d,pmin). Acceptance of a produced index uses the independent checker and its own arithmetic contract.

The shadow run follows the shift peel decisions and evaluates retained on the same eligible notices in the same order. These are notifications at which the queue needs a refreshed lower bound; already-queued notices and ready/degree shortcuts are excluded. Shadow timing is excluded from policy comparisons. Grouped counts cover every such notice by k, current degree, and deletions since exact evaluation. only_*_above_T counts raw bounds exceeding the attained threshold while the other does not, before applying the structural floor. This is an opportunity to defer. Actual repeated evaluations, distinct re-evaluated vertex-level pairs and recurrence cells are measured for the three executed policies. Every 1,021st shadow notice also gets a fresh truncated-DP estimate over its surviving edge sequence. The tightness file reports slack against this numerical diagnostic split by the probability range of the surviving edges.

The one-factor controls start from Shift. They disable the global pmin structural floor, set shared shortcut tolerance to zero, disable both sweep and PMF trimming (kTau=0, including grouped seed rows), turn on the existing Hoeffding screen, or alter the offset ladder. The powers-of-two ladder has one offset per octave. The denser ladder uses up to four. Duplicate integer offsets at low degrees are removed. cap8 keeps the original ladder through 8 and the terminal zero-bound sentinel. Setting tolerance to zero still permits exact comparison with the attained threshold and the structural degree shortcut. Each resulting table has its own checked Dminus and Dplus.

To rerun on Windows with MSVC, execute these stages sequentially from this directory. Add --inputs to locate prepared graph directories and --work to select the scratch directory for binaries, values and orders. The runner rejects existing observation files. For a new series, use a fresh copy excluding logs, summary.csv, groups.csv and tightness.csv.

    python run.py build
    python run.py first
    python run.py repeat
    python run.py shortcuts
    python run.py legacy
    python run.py shadow
    python run.py report

The build stage checks the retained binomial helper against exact Python rational arithmetic on endpoint, mixed and adversarial probabilities before timing. logs/build.json records source and binary hashes and compiler flags. The logs folder keeps all build and verifier logs, elapsed wall times, graph and output hashes and work counters. Value and order files are reproducible scratch outputs.

The two additional legacy-kernel arms reproduce the original local OptiUCF numerical implementation of Eq. (8): Boost.Math standalone ibeta, binary64 top-k products and a 1e-13 guard. Both still emit orders for the independent checker. The guard is empirical. Comparing these arms with the directed-endpoint variants separates the choice of arithmetic backend from the lower-bound formula. The runner uses the project’s existing standalone Boost.Math include tree. Supply --boost to select another copy. [Sun et al., Eq. (8)](https://arxiv.org/html/2504.20795v1#S4.SS1).
The numerical-kernel control used [Boost.Math f1b0b95](https://github.com/boostorg/math/tree/f1b0b95a04f56717b3454cb599e0647770c5852e). The two input JSON manifests give the source revisions, preprocessing rules, and SHA-256 hashes for the complete graph files.
The no-floor option bypasses use of the per-vertex structural floor in peeling. Both arms retain the common binomial table initialization (1,378 scalar recurrence entries on Twitter and 561 on CN15k); the timed difference isolates use of that floor. The sampled DP diagnostic is ordinary binary64, so a sub-ulp negative slack against this diagnostic is reported in max_observed_overshoot.
